| [0025](0025-ci-job-isolation.md) | CI job isolation: any number of jobs per host; job-scoped state (TMPDIR, clean-up, temp sweeps) in the runner's own job folder, kept folders (build, checkout, caches, test browser) per slot from one declared list, `job-isolation.sh` the only way to the CI home (proposed) |
| [0026](0026-shared-dialog-api.md) | The shared dialog API: contracts declared in Rust with generated TypeScript, `DialogFrame` with declared actions (order, Enter, focus, busy), windows created hidden and shown at a ready handshake, `pd.confirm`, the test kit and each app's migration |
| [0027](0027-table-layers-and-sticky-headers.md) | Table layers: sticky headers above their rows (`--pd-z-table-*` ladder, conformance C43, `expectHeaderOnTop`), and `pd-table` built on Angular Material's table (sticky header, `matSort`, `mat-menu`, `matTooltip`, `matIconButton`) with group rows, middle truncation, `hideBelow`, row heights and the grid keyboard on top |
| [0028](0028-about-and-deps-crates.md) | `paddock-about` (About, legal texts, What's New and the `notices!()` macro, out of the updater) and `paddock-deps` (one typed dependency inventory: SPDX policy with scoped exceptions, byte-identical notices, CycloneDX 1.6 SBOMs for every app, lockfile readers for Pacenotes that never run a build) (accepted) |
| [0029](0029-the-shell-owns-the-start.md) | The shell owns the start: `Builder::tray`, `Builder::launch` and `Builder::add_to` open the tray and the main window after every plugin is set up; windows refuse to be built inside a plugin hook; every app tests its start (`paddock_shell::testing::start`, C50) (accepted 2026-10-29 by the user, after review rounds 1-2) |
| [0031](0031-patience-not-wall-clocks.md) | Patience, not wall clocks: stalls judged on call progress, CPU time and run state in host ticks (starved and stopped are not stuck), one injected `Patience` policy in `paddock-jobs` with the OS probe in `paddock-proc`, caps on a host-tick clock, check C51 over every bound; Debrief first, shared crates after the Dyno, Spotter and Pitwall 1.1 tags (accepted) |
| [0030](0030-unexplained-browser-aborts-name-their-cause.md) | Every unexplained browser abort names the causes it ruled out (the trace, the network service restarted, unchanged or unknown), each named cause has a real-browser test, one driver (`paddock-chromium`); reload once after a loss stays proposed until Windows CI shows it (proposed) |
| [0032](0032-windows-binaries-link-the-c-runtime-statically.md) | Windows binaries link the C runtime statically: `+crt-static` for every `*-pc-windows-msvc` target in the root `.cargo/config.toml` (sidecars were importing `VCRUNTIME140.dll`; Tauri only covers the main binary), and `conformance/release/windows-crt-imports.mjs` checks every installer build (proposed) |
| [0033](0033-processes-by-identity-never-by-a-bare-pid.md) | Processes by identity, never by a bare pid (rule 53): `paddock_proc::ProcessId` (pid plus start time) checked before every kill (one handle on Windows, a pidfd on Linux), per-pid and table walks follow parents by age, Windows supervised trees are their job's members, Clippy `disallowed-methods` plus check C53 over every kill site and open follow-up (accepted 2026-10-30 by the user) |
| [0034](0034-one-implementation-per-mechanism.md) | One implementation per mechanism (rule 55): the copies register `docs/known-copies.toml` (canonical, each copy's owner and delete-by tag), a fix touches every copy in the same change or waives it with a `Copies-waived:` trailer (only non-test source counts; wiring held to its tag), entries leave only with their files, freezes do not stop such fixes, date moves name their approver, tags refused for expired copies; check C58 (accepted 2026-10-31 by the user) |
| [0035](0035-widget-layouts-are-shared.md) | Widget layouts are shared: `paddock-widgets` (placements, a closed catalogue per app and surface, limits, lenient versioned reading, edits with one-level undo, the widget state envelope, generated TypeScript) and `@decryp7/paddock-ui/widgets` (widget area, frame, chooser); Dyno moves its dashboard, menu-bar items and the new popup widgets onto it in 1.0 and deletes its copies (accepted 2026-10-31, after review rounds 1-2) |
| [0043](0043-dialogs-size-to-content.md) | Dialogs size to their content (WPF `SizeToContent`): a size mode per kind (Manual, Height), one measure loop in the page with a last-sent baseline, epoch and seq, all sizing on the main thread at the OS edge (`GetDpiForWindow`, `AdjustWindowRectExForDpi`, `DWMWA_EXTENDED_FRAME_BOUNDS`, `WM_GETDPISCALEDSIZE`, a refit posted after `WM_DPICHANGED`), only a real resize switches to Manual; checks over every dialog kind and at 100/150 % and a DPI change on Windows; ships in Dyno 1.1.0 (accepted 2026-11-03) |
