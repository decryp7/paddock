# Amendment to ADR 0077 (2026-11-10): a test's children start from a declared environment, and tests build fixture repositories instead of using the live one

- Status: Proposed (2026-11-10), revision 2. Drafted at the user's request of 2026-11-10 (ER-21 redesigns). The
  independent review of revision 1 (`f0979961a`) approved it with P2s; revision 2 answers them. Needs the decisions below.
- Amends: ADR 0077 (tests never reach the machine's system services; accepted 2026-11-09), §3 ("who sets the marker":
  `paddock_testkit::command(..)`, the kit's child-process builder, which does not exist yet) and §4 (the static check). 0077
  keeps a test from reaching the machine's *services*; this amendment keeps the machine's and the runner's *environment and
  repository* from reaching the test. Same owner (the test kit), same builder, so an amendment rather than a new ADR.
- Related: ER-12 (deterministic tests), ER-14 / rule 7 (tests never touch the user's machine), ER-21 / rule 40, ER-27,
  ER-33 / rule 71, rule 49 (no patch left behind), rule 55 (one implementation per mechanism), ADR 0021 (portable tests,
  `paddock-testkit`), ADR 0033 (`paddock_proc::command`, Clippy `disallowed-methods`), ADR 0060 (every check runs
  somewhere), ADR 0078 (one shared test scratch), and the push gate in the ADR 0038 amendment of the same date (its git hook
  depends on this one, Evidence 4).
- Evidence read at `origin/train/2026-11-09-3` `66b600669` and in the job logs the coordinator saved in the session scratch
  folder (`triage-7872-7873/`, read 2026-11-10). Evidence 4 is a synthetic experiment in this researcher's scratch folder.

## Trigger

Run 7872 (train 3, `66b600669`), job 34390, `paddock-dev (macos-latest)`, two failures, each caused by something the
test did not declare:

1. `wrapper::without_a_compiler_the_wrapper_runs_a_cached_binary_or_points_at_rustup` (`tools/paddock-dev/tests/it/wrapper.rs:449`)
   expected `running the newest cached tool binary`; the wrapper printed its CI wording
   (`::warning::./dev: rustc is not available on this runner ... running the newest cached binary (...)`) because the
   test's child `sh dev` inherited `GITHUB_ACTIONS=true` from the CI job. The same file's `shell()` helper removes only
   the variables that feed the hash; `dev` reads 15 variables, `GITHUB_ACTIONS` among them at four places (`dev:32`,
   `:92`, `:198`, `:296`).
2. `golden::live_workflow_action_and_script_edits_narrow_exactly_as_affected_mjs_does` (`golden.rs:614-620`) runs
   `git clone -q --shared <repo_root()>`. In CI the repository is the kept clone: depth 1, `filter: blob:none`, sparse
   (`kept-clone: ready ... profile lean`). The clone failed: `remote: fatal: could not fetch 49f74c76... from promisor
   remote`, `lazy fetching disabled`, `fatal: early EOF`. On a developer's full checkout it passes, so the test's result
   depends on how the runner checked the repository out.

4. **Inherited git variables redirect a fixture repository into the real one (verified).** git 2.56.0, synthetic
   repositories: a `pre-push` hook in a **linked worktree** (where every agent works, rule 2) sees
   `GIT_DIR=<repo>/.git/worktrees/<name>` (in the primary checkout it does not). A hook that does what a fixture builder
   does (`mktemp -d`, `git init -q -b main`, `git commit --allow-empty -m "fixture commit from a test"`) **committed into
   the worktree's own branch**: `before: 5e3e0be chore: c`, `after: 8f906d2 fixture commit from a test | 5e3e0be ...`,
   with only `warning: re-init: ignored --initial-branch=main` on stderr. The same holds for any test run under `git
   rebase --exec`, a `git bisect run` script, or the integrator's per-commit gate if it runs from a hook. Git documents
   that hooks get these variables exported ("Environment variables, such as GIT_DIR, GIT_WORK_TREE, etc., are exported so
   that Git commands run by the hook can correctly locate the repository", https://git-scm.com/docs/githooks, read
   2026-11-10). So the push gate (ADR 0038 amendment of the same date) must not run tests until this amendment's helper
   is in use, or must clear `GIT_*` itself. The push gate's hook shims (ADR 0038 amendment, A2) do unset every `GIT_*`
   variable before they start anything, so the **git-hook path is safe without this amendment**; the dependency that
   remains is for tests started under `git rebase --exec` or `git bisect run`, and for the other inherited variables
   (`CI`, `GITHUB_ACTIONS`, `RUSTC`, `CARGO_*`), which the shims do not touch.

## Pattern

**A test's result depends on state it did not declare: the environment its runner inherited (CI vendor variables,
`GIT_DIR`, `RUSTC`, `CARGO_*`, `TMPDIR`, locale) or the shape of the checkout it runs in (depth, filter, sparse
profile, untracked files).** Each fix so far removes one variable from one child or skips one test on one runner.

**Invariant.** A process a test starts gets only the environment the test declares on top of one documented base, and a
test that needs a git repository builds one; a test that checks the live repository says so and verifies its
precondition (fails in CI, never silently passes, rule 71).

## Change

### 1. `paddock_testkit::child`: one way for a test to start a process (Rust)

This is the child-process builder ADR 0077 §3 calls `paddock_testkit::command(..)`; it is named `child` because
`command` collides with `paddock_proc::command`, which it wraps. ADR 0077 §3's table row is updated to the new name, and
`child` is what sets the run marker on every child.

```text
pub fn child(program: impl AsRef<OsStr>) -> TestCommand     // wraps paddock_proc::command (no window, ADR 0033)
impl TestCommand {
    pub fn env(&mut self, k, v) -> &mut Self;                // declared additions
    pub fn pass(&mut self, names: &[&str]) -> &mut Self;     // copy named variables from this process, by name only
    pub fn toolchain(&mut self) -> &mut Self;                // PATH entries and RUSTUP_HOME, CARGO_HOME, RUSTUP_TOOLCHAIN
    pub fn git(&mut self, scratch: &Scratch) -> &mut Self;   // isolated git: see below
    pub fn output(&mut self) -> Output; pub fn status(..); pub fn spawn(..) -> paddock_proc::Supervised;
}
```

- **The base** (always, after `env_clear`): `PATH`; on Windows `SystemRoot`, `windir`, `ComSpec`, `PATHEXT`,
  `SystemDrive` and `ProgramData` (passed from the host: many Windows APIs fail without them); `HOME`, `USERPROFILE`,
  `APPDATA`, `LOCALAPPDATA`, the `XDG_*` folders and `TMPDIR`/`TEMP`/`TMP` in the test's scratch (ADR 0078); `LANG=C.UTF-8` and
  `LC_ALL` unset; the run marker of ADR 0077 §1 (`PADDOCK_TEST_RUN`, and `NEXTEST_RUN_ID` passed through). Nothing else:
  no `CI`, `GITHUB_*`, `GITEA_*`, `RUNNER_*`, `GIT_*`, `CARGO_*`, `RUSTC*`, `RUSTFLAGS`, `PADDOCK_*` unless declared.
- **`git()`**: `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=<scratch>/gitconfig` (identity, `init.defaultBranch=main`,
  `core.autocrlf=false`, `core.eol=lf`, `commit.gpgsign=false`, `protocol.file.allow=always`), `GIT_CEILING_DIRECTORIES`
  at the scratch root, and none of `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`,
  `GIT_OBJECT_DIRECTORY` (the base already cleared them; Evidence 4's positive control proves it).
- **Logs (ER-27).** On a failed status the helper's assertion prints the program, arguments, working folder, the
  *names* of the variables it set (values only for the base and declared-safe names), the exit code and the last 40
  lines of stderr.
- **A test's own mode is declared.** A test whose precondition is missing reads `PADDOCK_TEST_MISSING=fail|skip`, never
  `CI` or `GITHUB_ACTIONS` (`golden.rs:24`, `:38`). The value is per leg: `job-tmpdir.sh setup` (the one writer of the
  job's test environment, next to ADR 0077's marker) writes `fail` on the Linux container legs, which have node and a
  full clone (as `golden.rs:20-23` assumes today), and `skip` on host legs unless the job declares otherwise; locally the
  default is `skip`, which prints a note.

### 2. `@decryp7/paddock-e2e/child` (TypeScript and `.mjs`)

`spawnTest(cmd, args, { env, git, cwd })` and its sync twin build the same base and pass Node an explicit `env`
object; `git: scratch` adds §1's git block. Share first (rules 42, 55): `conformance/src/hermetic.mjs` already has
`hermeticEnv(scratch, base)` (C14's dynamic part), which points the per-user locations into a scratch folder on top of
`base = process.env`. It becomes the TS canonical: its default `base` changes from `process.env` to the declared base,
`conformance/test` and `scripts/*.test.mjs` use it through `conformance/test/support/child.mjs`, and
`@decryp7/paddock-e2e/child` (a package that cannot import from `conformance/`) is registered in `docs/known-copies.toml`
as its copy with a golden test comparing the two environments and the Rust base list.

### 3. Fixture repositories instead of the live one

- `paddock_testkit::repo::FixtureRepo` (and `fixtureRepo()` in TS): `new(&scratch)`, `.write(path, text)`,
  `.copy_from_tree(&["scripts/affected.mjs", ".gitea/workflows/ci.yml", ...])` (copies named *files of the working
  tree*, never objects or history), `.commit(msg)`, `.branch`, `.tag`, `.merge`; every git call goes through §1's
  `git()`. The 18 hand-made builders of Evidence 3 move onto it.
- `golden::live_workflow_...` copies the files it edits into a `FixtureRepo` instead of `clone --shared`.
- **Repo checks are a declared kind.** A test that checks the live repository's own content (`contracts.rs`, `tree.rs`,
  `golden.rs:106`) calls `paddock_testkit::repo::live(&Needs { paths: &[...], history: History::None | Full })`, which
  verifies that the named paths are in the checkout (sparse profile) and, for `Full`, that the clone is not shallow and
  has no partial filter, and otherwise **fails** under `PADDOCK_TEST_MISSING=fail` and skips with a note under `skip`. The
  first-parent history test declares `History::Full` and runs only in the job that fetches it (registered in
  `docs/gates.toml`, ADR 0060), not in the kept-clone leg.

### 4. The check (number on acceptance): a scan with a ratchet, and a poisoned-environment run

- **Static scan** (conformance, over every Rust test file, every `#[cfg(test)]` module found by a syn pass, and every
  `*.spec.ts`, `*.test.{ts,mjs,js,cjs}`): flags `std::process::Command::new`, `tokio::process::Command::new`,
  `paddock_proc::command`, `Command::new` on an imported alias, `child_process` imports and their `spawn*`/`exec*`/`fork`
  calls, `git clone` or `--shared` of a repository root, and reads of `CI`, `GITHUB_*`, `GITEA_*`, `RUNNER_*` in test
  code, outside `paddock_testkit::child`, `paddock_testkit::repo`, `@decryp7/paddock-e2e/child` and the support re-export.
  Today's sites start in a shrink-only ratchet (`docs/hermetic-tests.toml`: file, count, owner, next tag of its app); a
  new site fails at once. It prints the files and sites it scanned; 0 files is `check broken` (rule 71).
- **Positive controls of the scan:** fixture files with each pattern (a bare `Command::new("sh")` in a `tests/` file, a
  `use std::process::Command as C; C::new(..)`, a `#[cfg(test)] mod` spawning `git`, `execFileSync('git', [...])` in a
  spec, `std::env::var("GITHUB_ACTIONS")` in a test) must each be flagged; the helper modules themselves must not.
- **Runtime positive control** (a test in `paddock-testkit`, and its TS twin, run on the Linux, macOS and Windows legs): with `GITHUB_ACTIONS=true`, `CI=true`,
  `GIT_DIR=<decoy>`, `RUSTC=<missing>`, `CARGO_TARGET_DIR=<decoy>` set in its own process (`EnvLock`), a child started
  by the helper prints its environment and none of them is there; a `FixtureRepo` built under that `GIT_DIR` leaves the
  decoy repository unchanged (Evidence 4 as a test).
- **Poisoned-environment nightly leg (D3):** the Linux nightly first builds the test binaries under a clean
  environment (`cargo nextest archive`, and the Node suites need no build), so the decoys cannot change the build itself;
  then it runs the archive and the Node suites with the decoys above exported and `GIT_DIR` pointing at a throw-away
  repository whose `HEAD` it checks afterwards. It finds what the scan cannot see (product code under test that reads the
  environment directly, a helper bypassed through a crate it calls). A difference from the plain run fails with the test
  names. A separate locale leg (`LANG=tr_TR.UTF-8`, `TZ=Pacific/Chatham`) runs only after `locale -a` shows the locale is
  installed in the image (else `check broken`), so a locale failure is not confused with an environment leak.

## Alternatives

- **A deny-list per child** (today's practice, Evidence 1): each new variable is found by a red run.
- **Clear the whole test process's environment at start** (`EnvLock::hermetic` for every test): in-process code still
  sees the runner's environment before the lock, and it does not reach children started by product code under test.
- **A full clone for every test job** (D4 (b)): undoes ADR 0080's lean kept clone and still leaves the checkout's shape as
  an undeclared input.
- **Containers for every test**: host legs exist to test the host, so this is out of scope.

## Consequences

- A test's children see only what the test declares; CI vendor variables and git's hook variables cannot change a
  result. Tests that relied on inherited `PATH` additions (a tool installed into a job-only folder) must `pass` them by
  name, which WP-5 and WP-6 find.
- Tests that read the live repository say so and fail loudly in the legs that promise their precondition.
- One more nightly Linux job (about the duration of the Rust and Node suites).

## Rollback

`child` can fall back to an inherited environment behind one constant (`INHERIT_FOR_ROLLBACK`) without touching the call
sites; the scan's ratchet can be frozen. `FixtureRepo` has no rollback need (it only replaces clones of the live repo).

## Decisions for the user

| # | Question | Options | Recommendation |
|---|---|---|---|
| D1 | Default environment of a test's child | (a) cleared, plus the documented base and what the test declares; (b) inherited minus a deny-list (`CI`, `GITHUB_*`, `GIT_*`, ...) | (a): a deny-list is today's per-test fix in one place, and the next variable is missed |
| D2 | The check | (a) the conformance scan with a ratchet plus positive controls; (b) a Clippy `disallowed-methods` entry only (Clippy cannot tell tests from product code, and does not see TypeScript) | (a), with `crates/clippy.toml` also gaining the `Command::new` ban the other nine files have, for product code |
| D3 | Dynamic check | (a) the poisoned-environment nightly leg (Linux); (b) none | (a): one Linux job a night |
| D4 | Tests that read the live repository | (a) behaviour tests use `FixtureRepo`; repo checks declare `live(Needs)` and fail in CI when the checkout cannot satisfy them; (b) give every test job a full clone | (a): (b) undoes ADR 0080's lean kept clone |
| D5 | Missing-precondition switch | (a) `PADDOCK_TEST_MISSING=fail\|skip` per leg, written by `job-tmpdir.sh` (`fail` on Linux container legs, `skip` on host legs and locally); (b) keep reading `CI`/`GITHUB_ACTIONS` in tests | (a) |
| D6 | Scope now | (a) all WPs; (b) the first cut (helper, fixture repo, scan with ratchet, `paddock-dev`, `heavy`, `wiki` and `paddock-repo-graph` tests), the rest per app before its next tag | (b) |

## Release impact (ER-31)

`paddock-testkit` and `@decryp7/paddock-e2e` are test-only; no shipped binary changes. Under D7 (a) no app tag waits for
this amendment; an app's own ratchet entries block that app's tag after the release in flight.
