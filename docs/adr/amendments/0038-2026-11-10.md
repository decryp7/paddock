## Pattern

**A check that exists is run only if the author remembers it, so failures it would catch in seconds reach CI and cost a
run each: accepted gates without an enforcement point.**

**Invariant.** No push leaves a worktree without ER-9's fast static gates having passed for what it pushes; the slower
local tests run beside the CI run they could cancel; CI's preflight runs the same command, so a skipped local gate
still fails fast.

## Change

### A1. `./dev push-gate`: ER-9's fast static gates, blocking

One Rust command (ADR 0022). Steps, all blocking, run in parallel within `heavy` and `CARGO_BUILD_JOBS=2` (ER-24):

| Step | What |
|---|---|
| 1 | commit-lint over the pushed commits (`paddock-conformance commit-lint --range`, exists), including ADR 0086's trailer form |
| 2 | conformance on the touched files: a new `--files` mode runs every check whose metadata has `granularity: "file"` (a new field; `scope` already means root/apps) on the touched files (C71, C15, C38, ...); app-level checks with `needs: none` run for touched apps |
| 3 | `cargo fmt --check -p <touched packages>` per workspace; `eslint --max-warnings 0` and the type-check of touched TS |
| 4 | lockfiles: `cargo metadata --locked --offline` for each workspace whose `Cargo.toml` or `Cargo.lock` changed (online once if the registry cache lacks a version); for npm, the consistency command WP-1 picks and proves with a positive control |
| 5 | `cargo clippy -p <touched packages> --all-targets -- -D warnings` on the host, and `cargo xwin clippy` for the Windows target of the same packages (ER-9), in the worktree's own build folder (`./dev target-dir`, ADR 0025 amendment) |

- **What it pushes.** The range is the commits the push adds: for a branch with no remote copy,
  `merge-base(origin/main, HEAD)..HEAD`; for a branch already on the remote, `<remote tip>..HEAD`. **Trains** (an
  integrator's branch made of merges) use the same rule: commit-lint runs on the new commits (merges included), steps 2-5
  run on the files and packages changed in `<remote tip>..HEAD` (the union of the merged branches' changes and the
  resolutions). The first push of a train therefore runs over everything it carries relative to `main`; later pushes only
  over what was added. A merged branch's own stamp is not trusted for the train (the merge result is new code).
- **Output.** One table: ran (duration), failed (with the exact re-run command), nothing skipped (all five steps always
  run); `::error::` lines in CI. Exit non-zero on any failure. It logs the files and packages it checked; a range with
  changes and 0 files checked is `check broken` (rule 71).
- **Time.** Agents run it in the background (`run_in_background`) and wait with `./dev wait --pid ... --max 20m`
  (ER-32), never in a foreground call that the Bash tool's 120 s timeout would cut. WP-7 measures the warm case and a
  **cold first push in a fresh worktree** (an empty build folder: step 5 is a full clippy of the touched packages) and
  sets `--max` from it.
- **Stamp.** A green gate writes `<git-common-dir>/paddock/push-gate/<head>.json` (head, input hash, steps, duration).
  The stamp is a **nudge, not enforcement**: an agent could write the file. Enforcement is CI's preflight running the
  same command (A3).

### A1b. `./dev push-tests`: the tests, after dispatch, in parallel with CI (ER-9)

Run after the push, in the background: the tests of the touched packages (`cargo nextest run -p <touched packages>`)
and the specs related to touched files (`vitest related <files>`), a subset of the affected plan (rule 3), through the
ADR 0077 amendment's child helper. Given the CI run id (`--ci-run <id>`), a failure **cancels that run at once** (ER-9
allows this without approval), prints the failing tests and the re-run command, and the author pushes once with every fix
(ER-10). The Linux container leg and timing-sensitive runs under load stay as ER-9 describes; `./dev check --pre-push`
(§3) remains the full local gate and calls `push-gate` and `push-tests` as its first stages.

### A2. Enforcement points

- **Git hook, tracked.** `tools/githooks/pre-push` (a POSIX `sh` shim that `unset`s every `GIT_*` variable git exported,
  then runs `./dev push-gate`) and `tools/githooks/commit-msg` (commit-lint), installed by `./dev hooks install`, which
  sets `core.hooksPath=tools/githooks` once for the repository (every worktree, Evidence 3). ADR 0083's `./dev worktree
  add` runs it; `./dev doctor` reports a repository without it. lefthook's entries are deleted (they never ran); its
  `pre-commit` fmt and clippy move into the gate (D4).
- **Agent hook, in ADR 0083's framework.** `push-gate` becomes a rule of the same Python matcher family as
  `own-worktree` and `no-pgrep-wait`, importing the shared `.claude/hooks/shellparse.py` (one parser, rule 55). It
  **exits 0 for every command that is not a recognised `git push`**. For a recognised push it resolves the effective
  directory exactly as ADR 0083 defines it (`cd` guarded or not, `git -C`, variables assigned earlier) and the head
  being pushed, and denies (exit 2, the cause and next step on stderr, ER-27) when there is no green stamp for that head
  ("run `./dev push-gate` in <worktree>, then push"), when the push carries `--no-verify` or `-c core.hooksPath=...`, or
  when it is a recognised push whose directory or head it cannot resolve (**fail closed only there**). It sets **no
  global `onFailure: block`** on the `Bash` matcher (that would block every Bash call when the hook fails). The same
  hook denies `Edit`/`Write` of `Cargo.lock` and `package-lock.json` (trigger 2; "use `cargo update -p` or
  `npm install`"). Its tests extend ADR 0083's case table (`own-worktree.test.sh`) with push cases, so both hooks share
  one fixture repository and one parser test set.
- **Bypass.** Only the coordinator, with `PADDOCK_PUSH_GATE_BYPASS=<reason>` on the command; the hook logs it to
  `<git-common-dir>/paddock/push-gate/bypass.log` and the landing summary counts it.

### A3. CI runs the same command

ADR 0080's preflight job runs `./dev push-gate --ci --range <base>..<head>` (D5: this is ADR 0049's push check, built
once). A head that skipped the local gate (bypass, forged stamp, a push from a machine without the hook) fails there in
minutes, before the long jobs.

## Alternatives

- **Build ADR 0038 §3's full `--pre-push` first.** Accepted a week ago and not built; it needs the Linux VM leg and is
  too heavy for every push. The fast tier ships first and §3 reuses it.
- **Run the tests before the push** (revision 1, within a budget): serialises what ER-9 runs in parallel and does not fit
  the Bash tool's timeout on a cold build.
- **Run the whole gate inside the agent hook:** can time out open (Evidence 4), and blocks the agent's turn.
- **Git hook only:** `--no-verify` skips it, and a forgotten install leaves a worktree unchecked.
- **lefthook:** never installed in five weeks; needs Node in the hook path.

## Consequences

- An agent's push of a red static gate is refused locally; a CI run is no longer the first place C71, fmt, clippy or a
  broken lockfile shows.
- The first push of a branch in a fresh worktree waits for a cold clippy (WP-7 measures it); later pushes are warm.
- One more Python rule in ADR 0083's hook family; one parser.

## Rollback

`git config --unset core.hooksPath` turns the git hook off for every worktree; removing the `push-gate` entry from the
tracked `.claude/settings.json` turns the agent rule off; the preflight job keeps running the command.
