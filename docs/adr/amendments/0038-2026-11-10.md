3. **Git hook facts (verified, git 2.56.0).** `git push --no-verify` skips `pre-push` (a hook that exits 1: plain push
   rc 1, `--no-verify` rc 0). `core.hooksPath` set in the primary checkout is seen by every linked worktree (shared
   config). A `pre-push` hook in a linked worktree gets `GIT_DIR` exported, so a test fixture's `git init` and `commit`
   run from it land in the agent's own branch (the ADR 0077 amendment, Evidence 4); git documents the export
   (https://git-scm.com/docs/githooks, read 2026-11-10).

4. **Claude Code hook facts** (https://code.claude.com/docs/en/hooks, read 2026-11-10): a `PreToolUse` command hook
   blocks a call with exit code 2 (stderr is the message) or `permissionDecision: "deny"`; its default timeout is 600 s;
   "On `PreToolUse`, a timed-out ... hook doesn't block the tool call" unless `"onFailure": "block"` is set (v2.1.295 or
   later). A hook that runs the whole gate inside the tool call could therefore time out open; a hook that checks a stamp
   cannot.

5. **Rule 5 is checked only by reading.** Rule 5's 2026-10-30 amendment has the reviewer revert the fix and run the new
   test, by hand; the 2026-11-05 user decision asks for "a failing run shown for every new test" in every brief (memory
   `redesigns-2026-11-05`). On `origin/main` since 2026-11-03, 316 commit subjects start with `fix`; nothing machine-readable
   says which test failed first. ADR 0038 A2 wants every commit of a landing green, so a red "test first" commit is not an
   option either.

## Pattern

**A check that exists is run only if the author remembers it, so failures it would catch in seconds reach CI (or
review) and cost a full run each: accepted gates without an enforcement point, and a rule (failing test first) with no
record a tool can verify.**

**Invariant.** No push leaves a worktree without the fast gate for its range having passed on that exact head (or a
declared, logged bypass by the coordinator); every `fix:` commit names the test that fails without its fix, and a
replay shows it.

## Change

### Part A. `./dev push-gate`: the bounded fast tier of `--pre-push`

One Rust command (ADR 0022), run from a worktree, over the range `merge-base(origin/main, HEAD)..HEAD`:

| Step | What | Bound |
|---|---|---|
| 1 | commit-lint over the range (`paddock-conformance commit-lint --range`, exists), incl. Part B's trailer form | seconds |
| 2 | conformance on touched files: a new `--files` mode runs every check whose metadata says `scope: file` (C71, C15, C38, C30's successor, ...) on the touched files; per-app checks with `needs: none` run for touched apps | seconds |
| 3 | `cargo fmt --check -p <touched packages>` per workspace; `eslint --max-warnings 0` on touched TS | seconds |
| 4 | lockfiles: `cargo metadata --locked --offline` for every workspace whose `Cargo.toml` or `Cargo.lock` changed (online once if the registry cache lacks a version); `npm ci --dry-run --ignore-scripts` consistency for a changed `package.json` or `package-lock.json` (WP-1 confirms the exact npm command and its positive control) | under 1 s per workspace (Evidence 2) |
| 5 | `cargo clippy -p <touched packages> --all-targets -- -D warnings` in the worktree's own build folder (`./dev target-dir`, ADR 0025 amendment) | budget |
| 6 | affected tests: `cargo nextest run -p <touched packages>` and `vitest related <touched files>`, through the ADR 0077 amendment's child helper, with `GIT_*` cleared first | budget |

- **Budget.** Steps run cheap first, with `heavy` and `CARGO_BUILD_JOBS=2` (ER-24). Steps 1-4 always run and always
  block. Steps 5-6 run within a wall budget (default 5 min, D3); what does not fit is printed `skipped (budget)` and
  recorded, and does not block: CI's preflight runs it anyway.
- **Output.** One table: ran (duration), skipped (declared reason or budget), failed (with the exact re-run command);
  `::error::` lines in CI. Exit non-zero on any failure.
- **Stamp.** A green gate writes `<git-common-dir>/paddock/push-gate/<head>.json` (head, input hash, steps run and
  skipped, duration). A repeat push of the same head reuses it.
- **One command for every place.** The git hook, the agent hook (by its stamp), CI's preflight job (ADR 0080 F, as
  `./dev push-gate --ci --range <base>..<head>`) and ADR 0049's push check (D5) run this same command.
  `./dev check --pre-push` (§3) stays the full gate and calls `push-gate` as its first stage.

### Part A2. Enforcement

- **Git hook, tracked.** `tools/githooks/pre-push` and `commit-msg` (POSIX `sh` shims that `unset` every `GIT_*`
  variable git exported and run `./dev push-gate` / commit-lint), installed by `./dev hooks install`, which sets
  `core.hooksPath=tools/githooks` once for the repository (all worktrees, Evidence 3). ADR 0083's worktree tool runs it at
  creation; `./dev doctor` reports a repository without it. lefthook's `pre-push` and `commit-msg` entries are deleted
  (they never ran); its `pre-commit` entries move to the gate (D4).
- **Agent hook, tracked.** `.claude/hooks/push-gate.sh` in a tracked `.claude/settings.json` (with ADR 0083's guard
  hooks): on a Bash call containing `git push` (with or without `-C <dir>`), it resolves the worktree and the head being
  pushed and **denies** (exit 2) unless a green stamp for that head exists, with the message "run `./dev push-gate` in
  <worktree>, then push". It also denies `git push --no-verify` and a `-c core.hooksPath=...` override (both skip the git hook), and denies
  `Edit`/`Write` of `Cargo.lock` and `package-lock.json` ("use `cargo update -p` or `npm install`"). It runs only a
  stamp lookup, so it cannot time out open (Evidence 4); `"onFailure": "block"` is set as well.
- **Bypass.** Only the coordinator, with `PADDOCK_PUSH_GATE_BYPASS=<reason>` on the command, which the hook logs to
  `<git-common-dir>/paddock/push-gate/bypass.log` and the landing summary counts.

### Part B. Failing-first record, verified by replay

- **The record.** A commit whose type is `fix` and that changes non-test code carries
  `Failing-first: <test id>[, <test id>]` (`cargo:<package>::<binary>::<test path>`, `vitest:<file>::<name>`,
  `pw:<file>::<title>`) or `Failing-first-waived: <reason>` (no test seam: CI configuration, docs, a build script). The
  form is checked by commit-lint (step 1); the content by the replay.
- **The replay,** `./dev check failing-first <commit>`: in a scratch worktree at `<commit>^`, apply only the commit's
  test side (files under `tests/`, `*_tests.rs`, `*.spec.ts`, `*.test.*`, and hunks inside `#[cfg(test)]` modules found
  by a syn pass); run the named tests: they must **fail on an assertion or panic** (a compile error is reported as `not
  measured: the test needs the fix to compile`, D7). Then at `<commit>`: they must pass. The failing output's tail is
  printed and kept in the gate's stamp; the landing summary lists `Failing-first: <n> replayed red-then-green, <k>
  waived, <m> not measured`.
- **Where it runs.** In `push-gate` for the fix commits of the range (within the budget), and always in the integrator's
  landing step beside `--commits` (A3). It needs no red commit, so A2's "every commit green" still holds.
- **Why a trailer here, when ADR 0075 moved waivers out of trailers.** A waiver is an authority that may need
  correcting later; this trailer is a claim the replay checks before landing, while the branch can still be amended.
- Rule 5's reviewer mutation check stays (it tests the test's strength; the replay tests that it failed first).

| failing-first replay | a fixture repository with (i) a fix whose test also passes on the parent: refused; (ii) a proper fix: red then green; (iii) a test inside `#[cfg(test)]` in the fixed file: split and replayed; (iv) a trailer naming a test that does not exist: `check broken`; (v) a `fix:` commit without trailer: commit-lint refuses |
| meta | every new check registered in `docs/gates.toml` (ADR 0060) with where it runs |
