## The class (ER-21)

Privileged code trusts a folder tree because it checked or locked only the top folder. Folders made earlier inside
`C:\ProgramData` inherit `(A;CIID;DCLCRPCR;;;BU)`, which lets Users add files and folders. A standard user then plants
content that SYSTEM runs or reads, or swaps a folder for a junction during a delete.

|---|---|---|
| 1 | Dyno helper data folder before `790c6e100` (fake `SDDL_DYNO_HELPER_UNFIXED`, `trust_fake.rs:190`) | `790c6e100` locks it at creation; `git tag --contains` lists only `dyno-v1.1.0`. No workflow or Tauri config at `dyno-v1.0.0` names `dyno-helper`, so **no released Dyno made the weak folder**; only development builds did. Fixed anyway (user, D1). Dyno has its own repair copy (`protect.rs:166-296`). |

| 3 | Pitcrew rounds 2 and 3, `fix/pitcrew-service-caller-check` `ba0fda293` | `ensure_protected_root` (`protected.rs:257`), `settle_runner_dir` (`:138`) and `check_runner_folder` (`:70`) lock or check the top folder and its direct children only. Two gaps in the shared code: `walk_no_follow` (`trust_real/mod.rs:32`) reads by path (`read_dir`, then `node(path)`),
so a junction swapped in between the two calls is entered; and nothing refuses a hard link (Mozilla CVE-2019-11736).

## Comparable practice (ER-37)

Fetched 2026-11-11:

- **Windows Installer.** `LockPermissions` and `MsiLockPermissionsEx` give a listed object "an explicit security
  descriptor". Anything else gets "the attributes of its parent or container object"
  ([1](https://learn.microsoft.com/en-us/windows/win32/msi/lockpermissions-table),
  [2](https://learn.microsoft.com/en-us/windows/win32/msi/msilockpermissionsex-table)). Nothing repairs an existing
  tree.
- **`SetNamedSecurityInfo`** "propagates any inheritable ACEs to existing child objects"
  ([3](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setnamedsecurityinfow)). Through a planted
  hard link, that is the CVE-2019-0841 shape. `lock_dir_with` (`trust_real/windows.rs:194`) therefore uses
  `SetKernelObjectSecurity` on one object.
- **ProgramData** is "available to anyone using the computer"
  ([4](https://learn.microsoft.com/en-us/windows/win32/shell/csidl)). Project Zero: its "default permissions allow a
  normal user to create new files in its subdirectories"
  ([5](https://projectzero.google/2015/12/between-rock-and-hard-link.html)). I found no Microsoft page on how a
  service should lock its subfolder.
- **Docker.** On Windows, `setupDaemonRoot` calls `MkdirAllWithACL` with `SddlAdministratorsLocalSystem`
  (`"D:P(A;OICI;GA;;;BA)(A;OICI;GA;;;SY)"`), and only for folders it creates (`if dir.IsDir() { return nil }`)
  ([6](https://raw.githubusercontent.com/moby/moby/master/daemon/daemon_windows.go),
  [7](https://sources.debian.org/src/docker.io/26.1.5%2Bdfsg1-9/engine/pkg/system/filesys_windows.go)). On Unix it
  runs `chmod 0711` on the top folder ([8](https://raw.githubusercontent.com/moby/moby/master/daemon/daemon_unix.go)).
- **containerd** chmods its root to 0700 on upgrade from 0711. It touches only the top folder
  ([9](https://raw.githubusercontent.com/containerd/containerd/main/cmd/containerd/server/server.go)).
- **GitHub Actions runner** runs as NETWORK SERVICE by default. It adds one inheritable entry for a local group and
  does no walk ([10](https://raw.githubusercontent.com/actions/runner/main/src/Runner.Listener/Configuration/NativeWindowsServiceHelper.cs),
  [11](https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/configuring-the-self-hosted-runner-application-as-a-service)).
- **Mozilla Maintenance Service** (CVE-2019-11736) is the one SYSTEM service found that repairs an existing
  ProgramData tree. The fix: move the folder aside, recreate it, move the contents back, check for hard links, and
  lock files in use ([12](https://bugzilla.mozilla.org/show_bug.cgi?id=1551913)).

**The cheapest standard option** is the one Docker, containerd and MSI use: rights given at creation, on the top
folder, with trust resting on nobody having written there before (`create_dir_protected` here). Its upgrade answer
is "refuse a tree this version did not create" (about 3 days, revision 1's D1 (b)). The user chose Mozilla's shape
instead (D1 (a)), at about 10 days.

## Decision

### API: `paddock_service::privileged::adopt`

```rust
pub fn adopt_tree(port: &mut dyn TreePort, parent: &str, name: &str, policy: &TreePolicy) -> Result<Adopted, AdoptError>;
pub fn drain_quarantine(port: &mut dyn TreePort, parent: &str, name: &str, budget: Budget) -> Drained;
pub fn reset_tree(port: &mut dyn TreePort, parent: &str, name: &str) -> Result<(), AdoptError>; // Dyno's per-install reset

pub struct TreePolicy { pub id: &'static str, pub version: u32, pub keep: &'static [Keep],
                        pub max_entries: usize /* 10_000 */, pub max_time: Duration /* 30 s */ }
pub struct Keep { pub name: &'static str, pub what: What, pub need: Need }
pub enum What { File, Folder(&'static [Keep]) /* recursive; empty = every entry */, Roots /* children moved, each adopted on its own */ }
pub enum Need { Required, IfPresent /* missing is fine, failing is not */, Optional }
pub enum AdoptError {
    Container(Untrusted),                       // the parent fails verify_container: nothing touched
    Required { path: String, reason: Reason },  // a Required or IfPresent entry fails; it stays in the aside
    Busy { path: String, holders: Vec<String> },// still held open after the retries (P1-5)
    Squatted { path: String, owner: String },   // <name> appeared during the adoption (P1-2)
    TooLarge { examined: usize, limit: usize },
    Io { step: Step, path: String, error: String },
}
```

`TreePort` is a new small port (`TrustPort` is unchanged). Its operations act on handles that name an object:
`open_parent`, `list(dir)` (name, `Node`, link count), `open_child(dir, name)` (never follows; files open with
`FILE_SHARE_READ` only, so no write or delete while held), `create_dir_in(dir, name)`, `move_into(entry, dir, name)`,
`lock(dir)` (one object, no propagation), `write_owner_only(dir, name, bytes)`, `read_checked(dir, name)` and
`remove_no_follow(entry)`.

- **Invariants:** `create_dir_in` and `move_into` are create-new and no-replace. An existing name is an error, never
  adopted.
- **Names:** every generated name carries a random 64-bit number in decimal: `<name>.new-<r>`,
  `<name>.adopting-<r>`, `<name>.untrusted-<r>`. `inside_aside` already accepts the last one. After 8 collisions the
  result is `Io { step: NoFreeName }`.
- **The fake:** `FakeTree` in `trust_fake.rs` shares the nodes and SDDL fixtures of `FakePort`, plus alternate
  streams and extended attributes.

**The checks, all made on the open handle:**

- **Kept file:** a regular file, not a reparse point, link count 1, owner SYSTEM, Administrators or
  TrustedInstaller, and the full inside rule (`check_windows`/`check_unix`).
- **Kept folder:** a real folder, not a reparse point, with a trusted owner. **Its DACL is ignored**, because the
  folder is rebuilt: a new protected folder gets the entries that pass, and the old folder object, with its streams,
  extended attributes and any held handle, stays in the aside.
- **`Roots`:** each child is moved as an entry into the new folder without a content check. A link is moved by its
  own handle and never followed. Each child is then adopted on its own, with the new protected folder as its parent.
- **A name already in the new tree** (a resume, a re-registration): the new tree's entry wins, and the aside's stays
  and is listed in `left`.

### Steps

| # | Step | Crash after it → next run |
|---|---|---|
| 0 | Open the parent by handle; `verify_container`; else `Container` | — |
| 1 | **Finish or resume.** `<name>` is a real folder with a trusted owner and a valid marker (`.paddock-adopted`: owner-only, link count 1, this `id` and `version`): rename each trusted `.adopting-<r>` the marker names, and every trusted `.new-*`, to `.untrusted-*`, then return `already`. Else, if a trusted `.new-<a>` holds a valid journal (`.paddock-adopting`, owner-only) naming aside `<b>`, continue at the first step not done. Every other trusted `.adopting-*` or `.new-*` (a stale aside after a version bump) goes to `.untrusted-*` and is never resumed. "Trusted" means a real folder whose owner is read by handle without following a link. | — |
| 2 | Create `<name>.new-<a>` (protected at creation) and write the journal naming a fresh `<b>` | step 1 resumes from the journal |
| 3 | Rename `<name>` to `<name>.adopting-<b>` by handle, with retries. Skipped if `<name>` is absent. | the journal names `<b>`; the aside exists or `<name>` is still in place |
| 4 | Move back the kept set from the aside into `.new-<a>`, with retries | the moves are atomic; re-list and go on |
| 5 | Write the marker `{id, version, from: <b>}`, then delete the journal | the marker in `.new-<a>` means: go to 6 |
| 6 | Rename `.new-<a>` to `<name>` with no-replace. If `<name>` exists, someone squatted it in steps 3 to 6: return `Squatted` (owner SID logged). The next run moves the squatter to `.untrusted-*` (never read) and retries step 6. | step 1 finds the marker in `<name>` |
| 7 | Rename `.adopting-<b>` to `.untrusted-<b>` | step 1 finishes it |

The component is **blocked until `Ok`**. A crash at every point is a test.

**Held handles (P1-5).** Steps 3, 4 and 6 retry a sharing violation 6 times, with backoff from 0.5 s doubling to
8 s (about 30 s). Then `Busy` names the holders: Restart Manager (`RmRegisterResources`, `RmGetList`) over the files
found open below, by process name and pid, or "a program holds a file below <path> open" when it names none. The
component stays **blocked** (not failed), and the adoption retries every 60 s. That is logged once, then summed up.

**Draining (D2 (a)).** Only the latest failed aside per root is kept: it is named in the error and drained after the
next successful adoption of that root. Successful asides are drained at once. `drain_quarantine` locks each folder by
handle before listing it, so new opens are denied, removes a link by its name, and never reads anything. It is bulk
work (rule 52: utility QoS, `BELOW_NORMAL`): at most 50_000 entries or 60 s per pass, and it stops after 20 passes
with no progress. It logs a growing count every 5 s.

**Logs (ER-27).** Each step logs its outcome and duration with the root, policy id and version, an adoption id,
`kept`, `left` and the aside name. Errors carry the cause and the next step. Only entry names are logged, never
contents.

### Pitcrew (the Pitcrew agent adopts this for round-3 P1-1)

- **Data root** `%ProgramData%\Pitcrew`, at service start before anything is read. This replaces
  `ensure_protected_root`.
  - Kept: `pitcrew.toml` (Required), `pitcrew.toml.bak` and `state.json` (IfPresent), and `runners` (`Roots`).
  - `logs`, including `logs\blocked`, is not kept. The service makes it again inside the new root, where it inherits
    SY and BA full control and BU read and execute.
- **Each runner** `runners\<name>`, on a worker after the service reports running.
  - The runner shows as blocked, "securing its folder", until its adoption ends. This replaces `settle_runner_dir`.
  - Kept: `.runner` and `config.yaml` (Required; fix-it: register again), and `bin` (`Folder`, Optional). A managed
    binary that is not moved back is installed again from its checked release source before the first start.
  - `work`, `cache` and `logs` cost one rename each.
- `check_runner_folder` stays as the per-request check. A runner folder outside the data folder is checked, never
  adopted, and ADR 0004's limit (3) then applies only there (Program Files inheritance).

### Dyno helper

- `C:\ProgramData\Dyno` keeps `Helper` (`Folder`).
- `Helper` keeps:
  - `config.json`: Required at start (a failure leads to Repair), Optional at Repair, where setup writes it fresh.
  - `policy.toml`: IfPresent. If it failed and were dropped, visibility would fall back to the wider default.
  - `audit.jsonl`: IfPresent.
- `helper.log`, `tools` and `staging` are not kept.
- `TrustGuard::ensure` and `move_aside` are deleted. `reset_root` stays as the per-install reset, rebuilt on
  `TreePort` as `reset_tree`. The per-run `verify_tree` lists through `TreePort`.

**Unix.** Dyno's helper folders are root-owned 0755 system folders that users cannot write. Adoption runs the
bounded `verify_tree`; when it passes, it only writes the marker, and the move path runs only on a failure. The Unix
`TreePort` is costed mainly as test infrastructure for the core.

## Tests

Fake `TreePort` tests, written to fail first (ER-11):

1. **The v1.0.1 shape (P1-1):**
   - Fixture SDDL: `runners`, `runners\a` and `bin` get `O:SYG:SYD:AI(A;OICIID;FA;;;SY)(A;OICIID;FA;;;BA)(A;OICIIOID;GA;;;CO)(A;OICIID;0x1200a9;;;BU)(A;CIID;DCLCRPCR;;;BU)`, and files get `O:SYG:SYD:AI(A;ID;FA;;;SY)(A;ID;FA;;;BA)(A;ID;0x1200a9;;;BU)`. These are derived from ProgramData's inheritance; V1 captures the real ones.
   - After adopting the data root and then the runner, `.runner` and `config.yaml` survive, `bin` is protected, and
     an `evil.dll` a user owns in `bin\plugins` is in `left`.
2. **The Dyno 1.1.0 shape (P1-4):** a `policy.toml` with `others = "hidden"` still reads hidden after adoption. A
   user-owned `policy.toml` gives `Required`.
3. **Links:**
   - a junction in the middle;
   - an entry swapped for a junction between `list` and `move_into`;
   - a hard link (link count 2), which gives `Required`;
   - a junction named `.adopting-<r>`, which is never resumed or followed.
4. **Crashes and journal:**
   - a crash at every step and every call;
   - a crash between steps 5 and 7, where the aside is still drained;
   - a version bump with a stale `.adopting-*`, which is drained, never resumed.
5. **Names:**
   - root squat between steps 3 and 6, which gives `Squatted` and then a recovery;
   - name exhaustion;
   - a kept name already present after a re-registration.
6. **Other cases:**
   - a forged marker (a user owns it, or it is a hard link);
   - `Busy`, with retries, holders and the blocked state;
   - an alternate stream and an extended attribute on a kept folder stay in the aside;
   - draining locks before it lists and stops at its budget and pass cap;
   - an untrusted parent means no call that changes anything.

**Real ports.** Unix tests on the dev OS (symlink, hard link, `O_NOFOLLOW`). Windows tests on the CI runner
(junction, hard link, sharing violation, Restart Manager).

**Windows test VM rows** (`docs/testing/windows-test-vm.md`, standard user `paddock-test`; ER-33 positive controls

## Consequences

- One mechanism. ADR 0004's limit (3) is gone for trees in the data folder, and so are Dyno's repair copy and the
  second `.untrusted` sweep.
- An upgrade from `pitcrew-v1.0.1` loses old job folders, caches and logs. The release notes say so.
- The guarantee rests on adoption running before the first trust, on the create-new invariant, and on nothing ever
  reading inside an aside. The aside is not unreachable, because Windows does not check traversal for users; it is
  never read.
