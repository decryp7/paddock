# Amendment to ADR 0078 (2026-11-10): a reserved cache folder in the run root

- Status: Proposed (2026-11-10), with ADR 0095 revision 2, which needs it. An amendment to ADR 0078 (accepted
  2026-11-09). This file is merged into the ADR's own text when ADR 0095 is accepted; until then it stands next to it.
- Related: ADR 0078 §1 (the run root, its `.lock`, the sweep), §3 (the leak check), ADR 0095 §2 (`repo::once`), rule 53,
  ER-33.

## Trigger

ADR 0095 makes whole-repository setup (the raw `cargo metadata` of every workspace, later possibly a base copy) once
per test run, shared by every test process of the run. ADR 0078's leak check reports "anything left in the run root" as
an error (§3), so such a cache would fail every test job; and a cache outside the run root would need its own sweep, its
own lock rules and its own leak check.

## Change

1. **`<run root>/.cache/` is reserved.** Only `repo::once` (ADR 0095, `paddock-testkit-repo`) writes there, each artifact
   as `<key>` beside its own `<key>.lock`, built under `<key>.tmp-<pid>` and renamed. Nothing else in the family may
   create the folder; a lint fixture shows another writer is reported.
2. **The leak check exempts `.cache/` and nothing else.** `./dev check temp-leaks` does not report `<run root>/.cache/`
   and its entries; it still reports `<key>.tmp-*` leftovers (a build that died) and every other leftover in the run
   root. Positive controls: a planted leftover beside `.cache/` and a planted `<key>.tmp-1` are reported; a planted
   `.cache/<key>` is not.
3. **Removal stays with the exclusive-lock holder.** `.cache/` is removed only with the run root, by the process that
   gets the root's exclusive `.lock` without waiting (§1's sweep and the job's end-of-run removal). No test removes
   cache entries; a test never deletes another test's artifact.
4. **Rollback.** Withdrawing this amendment removes the exemption; a `.cache/` left behind is then reported like any
   leftover and removed with the root by the exclusive-lock holder.
