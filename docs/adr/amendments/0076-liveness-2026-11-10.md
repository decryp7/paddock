# Amendment to ADR 0076 (2026-11-10): owned children end through their handles, never through a process-table look

- Status: Accepted 2026-11-10 (user), with ADR [0081](../0081-process-liveness-is-three-valued.md) (§5), decisions as
  recommended. An amendment to ADR 0076 (accepted 2026-11-09), which is not on `origin/main` yet: it lives on
  `origin/docs/adr-0076-owned-background-work` (`a1fe4599c`). This file is merged into the ADR's text when that branch
  lands.
- Related: ADR 0081 (process liveness is three-valued: `Presence`, the `Alive` and `Departed` tokens), ADR 0033 §4
  (supervised children are held, not looked up), rule 53.

## Trigger

ADR 0081 makes every liveness decision three-valued and requires a proof token (`Alive`) before a signal. Read
literally, that would make 0076's owners (`Supervised`, `TaskGroup`, the reaper) look a held child up in the process
table before ending it, so an unreadable table (`Unknown`) would leave every owned child running.

## Amendment

**§2 and §2a:** ending an owned child goes through its handle and never waits on a process-table look.

1. A held, unreaped child is proof of life: `paddock-proc` mints `Alive` from the handle itself (`Alive::held(&Child)`,
   crate-private, while `try_wait` answers `Ok(None)`; the handle pins the pid, ADR 0033 §4). No process-table read.
2. Ending through the handle (`Child::kill`, `TerminateJobObject`, the process group while the leader is unreaped)
   needs no token at all.
3. An owner's "ended" report comes from the handle's wait status, which is proof (`Departed::reaped`).
4. Only a child that has been reaped, or a process the owner does not hold, goes through an ADR 0081 look.
5. The leak guard (§5) uses `paddock_testkit::proc::assert_gone`, which fails on `Unknown`.

The held-handle `try_wait` folds found by ADR 0081's survey (14 sites) stay 0076's territory: they are registered as
`held` in `docs/liveness.toml`, and their `Err` arm is made explicit when each file is next touched.
