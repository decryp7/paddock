# Amendment to ADR 0025 (2026-11-10): a kept build folder is keyed by the source it builds

- Status: Accepted 2026-11-10 (user), decisions as recommended (D0–D6; D0 accepts ADR 0025 itself; D6 (c): one wipe of the hosts' `target-*` folders after train 3 lands). Revision 2, after review rounds 1–3. Drafted at the user's request of 2026-11-10 (ER-21 redesigns). Revision 2
  answers the independent review of revision 1 (`f0979961a`: one P1 on the clean-up globs, six P2s). 
- Amends: ADR 0025 (CI job isolation), §2 (kept folders per slot), §4 (declared lists) and §5 and §6 (clean-up and disk),
  whose premise "cargo's build folder, whose fingerprints hold absolute paths" is wrong for workspace members (Evidence 2).
  ADR 0025 is still `Proposed` in its own header while its code runs on every host job: **accepting this amendment
  accepts ADR 0025 with it** (D0).
- Why 0025 and not 0080 or 0085: the defect is in how a kept folder is named and found (`kept-folders.txt`,
  `job-isolation.sh`, `build-folder.sh`), which ADR 0025 owns. ADR 0080 only added the second source root (the kept clone)
  that exposed it. ADR 0085 (accepted 2026-11-10) makes **tag runs** immune, because release mode builds in a job-local
  folder (its §4 item 1; its T5 names this class for tags), but it covers tags only: branch runs, rule 54 dispatches,
  nightly and the landing run still use kept folders, and those are the runs ER-31 and ER-33 judge a release on.
- Related: ER-20 / rule 51 (parallelism and cost), ER-21 / rule 40, ER-27, ER-28, ER-33 / rule 71, rule 2, rule 55 (one

## Pattern

**A build output kept between runs is reused for a different source whenever two source roots write one kept folder,
because the folder's key (app and job) does not name the source and cargo's freshness check does not either.**

**Invariant.** A kept build folder is only ever built from one source root; the folder records which root, toolchain,
commit, run and job last built it; a job that finds another root's record cleans the folder before building and says so
in its log.

## Change

### 1. The source is part of the folder's key

- `kept-folders.txt`: `target  target-{name}-{src}-{slot}  slot`. `{src}` is the first 10 hex digits of the SHA-256 of
  the canonical workspace root (`pwd -P`; on Windows `cygpath -m`, drive letter lower-cased), the folder given to
  `build-folder.sh`. `{slot}` stays last, so clean-up patterns keep their `{slot}` anchoring.
- `job-isolation.sh path target <name> --source <dir>` fills `{src}`; `path` refuses a `{src}` layout without
  `--source`. Linux keeps `<workspace>/target` (a new container each run, so already keyed by the root).
- **Every layout reader learns `{src}`** (Evidence 5): `slot_folders`, `legacy_folders` and `cmd_owns` read it as `*`
  (`?*` in `owns`, like `{name}`); `slot_anchored` takes the stem before `{name}` as today; `cmd_path`'s unslotted-layout
  migration skips layouts that contain `{src}` (an old folder cannot be attributed to a root). One shared helper,
  `glob_of <layout> <slot>`, replaces the five hand-written substitutions, so a sixth placeholder cannot be missed again.
- **The old folders are removed once.** `due` gains a `retired` reason: a folder is retired only if it matches a
  retired layout listed in `kept-folders.txt` (`# retired: target-{name}-{slot} 2026-11-10`) **and matches no current
  layout**. The retired glob `target-*-s<n>` also matches a current `target-<name>-<src>-s<n>`, so `due` first tests the
  folder against `glob_of` of every current layout, and the `{src}` segment is matched strictly as 10 hex digits before
  `-s<n>` (`[0-9a-f]{10}`), so a current folder can never be taken for a retired one. A retired folder is due at the
  slot's next idle sweep, under the slot's lock as today. The first job per slot and root is cold once.
- The golden fixture's stub `build-folder.sh` is updated in the same change if the script's imports change (it models
  them for the planner's recorded plans; rule 55).

### 2. A stamp records who built it, and a mismatch cleans

`build-folder.sh` (before the build) reads and writes `<folder>/.paddock-build-source`:

```text
format = 1
root = "c:/users/<runner>/.paddock-ci/src/paddock-checkout-windows-s2/apps/pitwall"   # canonical, as hashed
checkout = "kept-clone paddock-checkout-Windows"                                     # the action and its name
commit = "92e65ead4fb3..."
rustc = "rustc 1.99.1 (... 2026-...)"                                                # `rustc -V`, for the log only
run = 7873
job = 34416
written = 2026-11-10T05:19:11Z
```

- **Root differs** (a hash collision, a folder made by hand): the folder is renamed to `<folder>.stale-<run>` and
  deleted (the slot is held; `owns` now answers yes for it), with one `::warning::build-folder: <folder> was last built
  from <root> by run <run> job <job>; cleaned before building from <root'>`. **No stamp** in a non-empty folder: the
  same, with "no record of its source". **Toolchain differs:** logged only (cargo keys every unit by the compiler).
- **Log line on every job** (ER-27), replacing `build folder: <dir>`: `build folder: <dir> (source <root> at <commit>;
  last built by run <run> job <job> from the same source <age> ago)`, or `(new)`, or `(cleaned: last built from <other
  root>)`.
- There is **no after-build "verify" step** (revision 1 had one): in the incident cargo compiled nothing, so a check of
  what the build wrote cannot see it. The class is made impossible by the key (§1), the stamp guards the key, and the
  failing-first test below shows both.

### 3. One source per name in the workflows (static)

The existing `ci-actions.test.mjs` test "every job that builds Rust on a host sets its build folder with the build-folder
action, in a stable checkout" (`conformance/test/ci-actions.test.mjs:372`) gains an assertion: on the tree under test,
each build-folder `name` expression is paired with one checkout action and name. It cannot see a pairing on another
branch (run 7873 was `main` against train 3), which is why §1 keys by the root at run time.

### 4. Local build folders

`./dev target-dir <cargo-workspace>` prints the folder to use, `<targets-root>/<worktree-key>-<workspace-key>` (default
root `/Volumes/d7sst7/dev-targets/t`, set in `devkit.toml`; `heavy` already refuses one under `~`), and writes the same
stamp. On a root mismatch it **cleans only the path packages** (`cargo clean -p <pkg>` for every workspace member and path
dependency from `cargo metadata`), keeping registry crates, which do not depend on the root; WP-0 measures this against
a full clean (§5). `AGENTS.md`'s "kept between tasks for the same app" becomes "kept for the worktree; `./dev target-dir`
names it". The CI script and `./dev` share the stamp format and a golden test; the shell copy is registered in
`docs/known-copies.toml` until ADR 0022 moves the CI kit to Rust (rule 55).

### 5. Parallelism and cost (rule 51)

- **Disk.** One more folder per (slot, name, root) while two roots alternate on a slot (a transition like `main` against
  train 3); normally one root per name. The orphan sweep (14 days) and the free-disk floor bound it, now that they see
  `{src}` folders (§1).
- **Time.** CI: one cold build per slot and root, once; afterwards as warm as today. Cleaning on every mismatch instead
  (D1 (b)) would make every alternating job cold. Local, on a mismatch: a full clean rebuilds every crate; `cargo clean -p`
  of the path packages keeps the registry crates (most of a cold build's units). WP-0 measures both on one app (cold
  build, path-packages-only rebuild, warm build) and records them in `docs/benchmarks.md` before §4's default is fixed.
- **Threads.** Unchanged: `build-jobs` and `heavy` bound the builds as today.

## Alternatives

- **Clean on every root change, no key in the name** (D1 (b)): correct, but cold builds on every alternation.
- **Fix the instance:** after train 3 lands, `ci.yml` uses only the kept clone. The next checkout change reopens it.
- **cargo's `-Zchecksum-freshness`** (content hashes instead of mtimes): nightly-only and unstable; the family builds on
  stable (ADR 0022). Revisit if it is stabilised.
- **A job-local build folder for every run** (as ADR 0085 does for tags): correct, but every host job cold.

## Consequences

- A kept build folder can no longer serve another source; every job log says which source last built its folder.
- One cold build per slot and root at the switch; old folders are removed by the sweep.
- ADR 0025 §2's sentence about absolute paths is corrected and ADR 0025 is accepted with this amendment.

## Rollback

Revert `kept-folders.txt` to `target-{name}-{slot}` and drop `--source`; `glob_of` and the stamp stay harmless (cargo
ignores the stamp). Folders made under the new layout age out through the sweep.
