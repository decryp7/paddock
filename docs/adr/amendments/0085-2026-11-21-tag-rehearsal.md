# Amendment to ADR 0085 (2026-11-21): the tag rehearsal exception to items 9 and 10

- Status: Proposed (2026-11-21). Amends `0085-2026-11-12-wp4-wp9.md`, items 9 and 10; branch `feat/ci-tag-rehearsal`.
- Why: run 8384 and run 8395 failed only on a real tag, because a dispatched release run is release=0. `tag-rehearsal.yml` runs a tag's
  release path on main with `PADDOCK_TAG_REHEARSAL=1`, which `conformance/src/util/is-tag-run.mjs` answers as "tag".

1. **Item 9 (only `tauri build` and the pre-sign `sign` process get a key) is unchanged,** and the key is never the real one in a rehearsal:
   `updater-key.sh` fails the step before `npm ci` when any private key is in the environment of a rehearsal.
2. **Item 10 (the throw-away key) gains the rehearsal.** In a rehearsal the script always makes a key pair in the job, even when a public key is
   given, because the run is a "tag run" for every other decision. The refusal "a tag run has the public key but no private key" does not
   apply to a rehearsal (it has no real key by design); every other tag refusal still does.
3. **A rehearsal never meets a real tag.** `is-tag-run.mjs` exits 4 (a throw in JavaScript) when the switch is on and the ref is a tag, or the
   value is not 1, 0 or empty; every shell caller fails closed on any status other than 0 and 3. The workflow runs on main only, and
   app-release.yml's guard step refuses `refs/tags/*` and a missing switch.
4. **Nothing is published.** The `release` job is skipped by `inputs.rehearsal != true`, `publish-release` refuses the switch, and
   `rehearse-release.mjs` makes the notes and latest.json and reads them back without a publisher.
