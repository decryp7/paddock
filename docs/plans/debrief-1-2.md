# Plan: Debrief 1.2.0

- Status: Plan, 2026-10-27. Nothing here is built yet.
- App: Debrief (`apps/debrief`). Rule 1 holds: Debrief is the one app; the shared work below is done for Debrief's
  release and is adopted by the demos in the same change (monorepo rules 39 and 42), not as a separate Paddock project.
- Scope:
  1. Debrief adopts the Paddock shell and workbench released in 0.3.0 ([workbench.md](workbench.md) §2 inventory,
     §4.3 M1-M5, §14-16).
  2. ADRs 0016 (dialog sizing contract), 0017 (viewport and selection survive refreshes, scrollbar markers), 0018
     (bounded loading, virtualization by default, Lanes picker and "All", streaming imports), 0019 (limits explain
     themselves). Accepted 2026-10-27; on branch `docs/adr-rule40`, not yet on `monorepo/apps`.
  3. The plugin research ([2026-10-plugins-memory-and-manager.md](../research/2026-10-plugins-memory-and-manager.md),
     branch `docs/research-plugins`) WP-1 to WP-7, and the large-data part of the DuckDB research

     `docs/research-duckdb-2`) L1, L2, L3, L4, L5, L7, plus ADR 0018's CSV and JSON-array streaming (L6).

     on it (package 7.3) and does not repeat it.

## 2. Waves of work packages

Conventions for every package:

- One agent, own worktree of `paddock` (sparse: `crates ui scripts docs eslint conformance apps/debrief`), own
  `CARGO_TARGET_DIR`, own e2e port, `CARGO_BUILD_JOBS=2`, heavy jobs through the machine's slots (rule 41).
- Branch `debrief-1-2/<id>` from the integration branch `integrate/debrief-1-2`; the coordinator merges each package
  when its gates pass. Tests: what `scripts/affected.mjs` selects plus the touched specs, Playwright in Chromium only
  (rule 3). Lint and type-check the touched files. `CHANGELOG.md` (Unreleased) for shared changes,
  `apps/debrief/CHANGELOG.md` for Debrief's.
- Shared integration points (`apps/debrief/app/src/app/app.config.ts`, `app/src-tauri/src/lib.rs` command table,
  `api.types.ts`, `crates/Cargo.toml`, `apps/debrief/Cargo.toml`) take **one declared line per package**; anything more
  is done by the package that owns the file in that wave.
- A bug fix starts from its failing test (rule 5). Wave 0 writes those tests as `test.fail` / `#[ignore = "<reason>"]`
  so the integration branch stays green; the package that fixes the bug removes the marker as its first commit.
- Every shared package carries the full tests of its behaviour (unit, robustness, property, real OS where it matters)
  and is adopted by `shell-demo` or `workbench-demo` in the same change. A Debrief package that adopts a shared part
  deletes its own copy and the tests that duplicated it, and records test count and time before and after (rule 43).
- Within a wave the owned files do not overlap. A package starts when its dependencies are merged and a slot is free;
  waves are the order, not a barrier (slot filling, section 5).

Roles: **implementer** = Sonnet, mechanical, precise brief; **designer**, **reviewer**, **researcher** = Opus;
**scout** = Haiku (CI watching, logs, inventories). Every package is reviewed by a reviewer that did not write it before
merge (scout watches its CI run). Effort is agent-days of focused work including tests (±50 %).

## 4. Debrief 1.2.0 release checklist

1. **Minor bump to 1.2.0** in its single source (`tauri.conf.json`, the app crate's `Cargo.toml`, and whatever the
   version script derives); tests read it and check its shape (rule 6); `apps/debrief/CHANGELOG.md` from the
   Conventional Commits since `debrief-v1.1.1`.
2. **Intel Macs dropped**: macOS bundle is arm64 only; libduckdb per arch (`libduckdb-osx-arm64`) instead of the
   universal library, in `fetch-libduckdb.sh`, `app/scripts/libduckdb.mjs` and the CI image; `latest.json` has no
   `darwin-x86_64` entry; README and release notes say Intel Macs stay on 1.1.1. This also frees the later move to
   DuckDB 2.1 (WP-D7 decided).
3. **Shared updater key**: built with `PADDOCK_TAURI_UPDATER_PUBKEY`; this is Debrief's first monorepo release, so per
   ADR 0014's amendment it is signed with `DEBRIEF_TRANSITION_SIGNING_KEY` (secret present and whitespace-stripped,
   rule 25), and the bridge `latest.json` on the old repo points at it; every later release uses the shared key only.
   See decision D2.
4. **"Existing installs download once"** in the First launch section of the release notes (the `FIRST_LAUNCH`
   heredoc in `debrief.yml`), with the macOS Open Anyway and Windows SmartScreen steps kept.
5. **DuckDB 2.0** in (5.3) with the storage compatibility pin; release notes list the SQL console's changed semantics
   (`~`, `!`, `X''`, division by zero, NULL type, lambdas).
6. `cargo deny check advisories`; one CI build with bundles; the icon check; signing secrets stripped (rule 25).
7. Full suite once (section 3) on the commit to be tagged; that commit is not `[skip ci]`; tag `debrief-v1.2.0`; the
   release is built only by the tag workflow (rule 9); `debrief-latest` and the bridge move.
8. Verify the published artefacts: `codesign --verify --deep --strict` on the published DMG, install over 1.1.1 on
   each OS and check the update path (bridge then shared key), First launch text present.
9. Lessons from the release into `docs/lessons.md`.
