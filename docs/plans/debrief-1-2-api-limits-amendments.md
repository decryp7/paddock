# Amendments to the API design, section 4.6 (`paddock-limits`, packages 1.4 and B1)

Next to `docs/plans/debrief-1-2-api.md` (revision 5, on `docs/debrief-1-2-api`), so the packages that use `paddock-limits`
read the contract as built on branch `debrief/1.2-limits`. Each row is a point the design left open or that the code
had to settle. Rows marked **REVIEW** change behaviour and need a reviewer's opinion before the branch merges.

| Q | Design said | Built | Why |
|---|---|---|---|
| L1 | `SettingPath`, `Unit` named, not defined | `SettingPath(&'static str)`: dotted parts `[a-z][a-zA-Z0-9_]*`, at most 64 bytes, `const fn new`. `Unit` = `Bytes, Count, Ratio, Millis, Percent`, one per `Quantity` variant | Needed to compile; `Registry::check` requires default, min and max in the row's unit |
| L2 | `FieldPath(Box<str>)`, grammar in ADR 0065 | `FieldPath(Cow<'static, str>)`, same grammar (at most 64 bytes, `[a-z][a-zA-Z0-9]*` parts with one optional `[u32]`, never starting with `result`), plus `FieldPath::lit` as a `const fn` and `root()` | A literal in a `const` fails the build instead of a test; constructors take a `FieldPath`, not a `&str` |
| L3 | `Bounded::first(iter, row, of)` | Same, using the row default as the limit; plus `first_with(iter, row, limit, of)` for the value a Setting currently holds | A Setting's current value is not in the registry row |
| L4 | `CutRow<S>` "generated by the registry" | `CutRow::<S>::of(&ROW)` is a `const fn`; used in a `const` it fails the build for a stop row, a row that does not declare `S`, or a row that does not count items | Same guarantee without a generator; B3 may still generate the consts |
| L5 | `LimitId(&'static str)`, `Cut` deserializes | `LimitId::parse` validates the dotted lower-case syntax and interns the key (the text is leaked once per distinct key), **at most 4096 distinct keys**, then `BadKey::Full` | `&'static str` cannot come from the wire otherwise; the bound keeps hostile input from growing memory |
| L6 **REVIEW** | More than 32 cuts: "keep the first 31 by the position of their list in `result` (outer first, then index)" | The first 31 **in the order they were added** (`.and` order); the aggregate counts the rest | A constructor cannot know where a list sits in `result`. A caller that wants the spec's order adds cuts in that order. If the position order is required, `Cut` needs the position from the reply type (B3's generator) |
| L7 | `.and(cut)` on a second cut of the same list | A cut with the same `(of, limit)` replaces the earlier one in place (and is not counted again) | `TryFrom<BoundedWire>` refuses duplicates, so `.and` must not make them |
| L8 **REVIEW** | Message "Raise it in Settings -> Performance -> Plugin memory" (ADR 0019) | `LimitExceeded::message(&Registry)` writes "Settings -> <dotted path>", e.g. `performance.pluginMemoryMb` | The registry row has no display label. A label field on `LimitRow` (or the Settings schema lookup) would fix it; the UI shows its own ICU text keyed by `LimitId` anyway, so this text is for logs, the AI and a fallback |
| L9 | `LimitExceeded { id, limit, reached, scope }` | As specified; the Setting path and remedy come from the row via `message(&Registry)` | The design's struct has no path field |
| L10 | Constructors return values only | `Cut::counted`, `Cut::page` and the `Bounded` constructors panic when given a selection of another kind than the row's handle, or `from + shown` past the total. No user or I/O data can reach these: arguments are literals, registry rows, or counts the caller took from its own data; "nothing left out" returns `None`/complete | Illegal states stay unrepresentable; a programmer error is found by the first test that runs the call |
| L11 | `Cut::maybe(row, of, shown, selection)` | `CutRow<Maybe>` handle (selection kind `Maybe` in the row) | Instance 12 needs an unknown total with a real selection |
| L12 | Generated `core/generated/limits.ts` | Only `--features ts` declarations (`CutWire` is exported as `Cut`, `BoundedWire<T>` as `Bounded<T>`; counts are `number`); no file is written under `ui/` | The UI entry point is B2/2.3 |
