# Land a train (Paddock)

Arguments: `$ARGUMENTS` (the train branch first, then its members). Work in the integrator's locked worktree, never the main checkout. Rules: ER-8, ER-10, ER-12, ER-49; docs/rules.md 3 (i) to (k); docs/ci-schedules.md.

1. Merge each member into the train with `git merge --no-ff <member>`, one at a time. Before a member merges the train back, `./dev merge sync-member` lists the reverts to re-apply. Run it again after the member has merged the train (the sync tip): it then runs the fast static rows (conformance, gates-register, clippy, clippy-windows) on that tip and fails on a bad row (fix on the member, then re-sync; `--no-static "<reason>"` is the logged escape), and once they pass it pushes the tip as `sync/<member>` (integrator role only, with a lease) and dispatches the member's own narrowed CI run, printing the run id (`--no-trial "<reason>"` skips it, logged). Merge the member as `sync/<member>` so the trial's branch name matches.
2. After each merge, `./dev merge check` diffs it against its parents for stale reverts and dropped hunks (exit 5 is a finding). Answer a finding in the merge message (`Hunks-dropped:`, `Tests-removed:`, `Reverted:`) or take the member out. It also runs the fast generator checks the merge made due; a heavy generator (it builds a workspace) is named `deferred` and not run per merge (`--heavy-generators` runs it): the one `./dev gen check --base origin/main` of step 5 checks the whole train's union of them.
3. After each merge, `./dev merge check --gates` runs the fast member gate on the combined tree. A red member is pulled and sent back to its author; do not fix it on the train. The same call reads the member's trial run (`ci trial-verdict`, the verdict reader): a red trial blocks the member with one `::error::`, a running one is `still running` and not a pass (exit 6), and a head with no trial run is a warning while report-only (`--no-trial "<reason>"` skips it, logged). For the last member of the train run `./dev merge check --gates --gates-base origin/main <merge>`: the gate then plans the whole train's rows (each earlier member's rows are reused), so the push hook and the train-audits guard find a pass for the same tree and run nothing again. The gate reuses each member's own green rows (stored in the shared store when the author ran `--member-gate` on the member branch; the row says `reused (green at <time>)`): a Cargo row or a `tests`/`tests-linux` row of a workspace only that member touched. It runs again a row whose inputs no member passed: a workspace two members touched (with its path dependencies), a conflict resolution or train fix in it, a change to what the tests read outside it (`ui/projects/paddock-ui`, `.gitea`), another toolchain, nextest or CI image, a member whose own row did not pass, a row `dev` computes itself when `dev` changed, and always the repository-wide rows (conformance, gates register, the audits) and `tools/paddock-dev`'s tests. A hit needs the member's tree to equal the train's in the row's inputs, so a member runs its final member gate after merging origin/main (AGENTS.md, "Before hand-back"; user, 2026-11-25); a member branched from an older main misses wherever main changed since (docs/benchmarks.md, "Member gate reuse on a train"). CI's full run still covers the whole train. `--no-reuse` runs everything.
4. Number each `NEW-<slug>` rule: give it the next free number in docs/rules.md and replace every citation of `rule NEW-<slug>` across the tree (`git grep -n 'NEW-'`), as one train commit before the pre-push; C31 refuses a repeated number and warns on a placeholder left (docs/rules.md preamble, user, 2026-11-25).
5. Once, on the final combined tree: `./dev gen check --base origin/main` (every generator the train made due, the heavy ones the per-merge checks deferred; run it beside the member gate, it only reads the checkout) and `./dev check --pre-push`. A "not measured" row is not a pass; fix it or say so.
6. Push the train once.
7. Dispatch `ci.yml` on the train with `./dev ci dispatch ci.yml --ref <train-branch> --max <duration>`, then wait with `./dev wait --ci-run <id> --max <duration>`.
8. On red, fix and run a failed-only round first: dispatch with the `since_run` input set to the failed run number (`./dev plan --since-run <id>` shows the plan). Check that every failed test really ran in that round: not filtered out, not skipped. Use "rerun failed jobs" only for a suspected flake (ER-12). After any fix commit on the train, rerun the member gate on the new head (`./dev check --pre-push --member-gate --base <the head before the fix>`) before the push (train c retro).
9. When every round is green, dispatch one full run on the final head: a plain dispatch with no `base` and no `since_run`. Nothing lands without it (ER-10).
10. Land: fast-forward main to the train head (`git merge --ff-only`, never a rebase or squash), in the integrator's worktree. The merge queue (`./dev queue tick`) does this step when it runs the landing.
11. If the run was green with FLAKY tests of code the change did not touch, record them: `./dev ci fix-items --workflow ci.yml --sha <the landed commit>` (ER-12).
12. Scope record: for a workflow whose scope producer has no first green run yet, `./dev ci scope-record --workflow <file> --run <id>` (docs/ci-scope-first-runs.toml).
13. Reuse check: the push to main must reuse the train's verdict. Read the push run: `./dev ci reuse` logs `reuse=true` and no job starts. If a new full run starts, stop it and report why the verdict was not reused (ER-49).

Report the train head, the run ids (failed rounds and the full run), pulled members, fix items and the reuse result.
