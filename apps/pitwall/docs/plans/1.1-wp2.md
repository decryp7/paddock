## Where Pitwall stands (measured on the branch base)

- **Tokens.** `src/styles.scss` defines its own scale (about 90 custom properties per scheme: `--bg-*`, `--sp-*`, `--fs-*`, `--r-*`,
  `--text-*`, `--accent*`, `--ok/warn/bad/info*`, `--viz-*`, shadows) and its own Material theme over them; components use
  about 1,600 `var(--…)` references to it and none to `--pd-*`. `angular.json` loads none of paddock-ui's CSS.
- **Material.** Icons, tooltips, slide toggles and one progress bar are Material; buttons (`.btn`), fields, the select
  (`pw-select`), tabs, menus (`pw-row-menu`, `pw-context-menu`), the confirm (`pw-confirm-dialog`) and the toast host are
  Pitwall's own.
- **Shell.** The Rust app crate (`src-tauri`) has its own start, window, tray, app menu, native feel, quit and updater
  (`shell.rs`, `window.rs`, `tray.rs`, `app_menu.rs`, `native_feel.rs`, `quit.rs`, `updater.rs`; about 1,400 lines) on
  `tauri::Builder`, not on `paddock-shell`. The UI has its own sidebar and routes.
- **Dialogs.** Five in-page CDK dialogs: `pw-confirm-dialog` (11 call sites), `pw-create-app-dialog`, `pw-key-secret-dialog`,
  `pw-quit-dialog`, `pw-service-consent`. The slots panel is an anchored popover and stays one (ADR 0026 §7).
- **Layout.** `e2e/layout.e2e.ts` measures 22 states at 900, 1024 and 1280 px; its baseline holds 90 known problems
  (52 at 900, 25 at 1024, 13 at 1280), each a test that fails until the line is gone. `e2e/a11y.baseline.json` holds 4 axe
  routes.
- **No About, no notices.** There is no About window and no `THIRD_PARTY_NOTICES.md`.

## Shared-code changes Pitwall needs

None is needed for packages WP-2.1 to WP-2.3. Two may be needed later; each is checked first, in the package named, and done
only if the check fails:

1. **A Quit the app may ask about first** (WP-2.4). Pitwall asks "Quit, keep serving / Quit and stop serving" before it quits.
   `paddock_window::tauri::quit` marks the app as quitting before it calls the app's `exit_app` hook, so a hook that shows
   `pw.quit` and is cancelled would leave the window layer quitting. The check: whether the UI's `pd.app.quit` command can
   be contributed by the app (the menu routes it to the UI) so the app asks before it calls `app_quit`, and whether the
   tray's Quit is the app's own action. If not: a cancellable `Windows::before_quit` hook in `paddock-window` (about
   0.5 agent-day, failing test first), after the freeze.
2. **Translucent main window** (WP-2.5). Pitwall's main window uses Mica / vibrancy (`html.translucent`); the shared window
   layer has a material for the tray popover only. Proposed without a shared change: Pitwall's main window becomes opaque
   like every family window. A decision for the user; a shared `WindowConfig::material` is the alternative (about 1 day).

Everything else Pitwall needs is on `main`: `paddock_shell::Builder` with `tray`, `launch`, `add_to`, `windows`, `updater`
(About, What's new, Updates and the legal documents), `dialogs`; `paddock_dialogs::dialogs!`; `pd.confirm`; the pages frame;
`paddock_shell::testing::start` for the start test; `scripts/notices.sh` for the notices.

### WP-2.1 Tokens: `--pd-*` everywhere (no shared change)

- `angular.json` loads `paddock.css`, `controls.css` and `material.css` from `ui/dist/paddock-ui/css` (as Dyno does);
  `<html data-accent="pitwall">`; Pitwall's own Material theme and its own token scale are deleted from `styles.scss`.
- Every component style and template uses `--pd-*` directly; there is no bridge of the old names. Values between steps move
  to the scale (`--sp-5` 20 px → 16 or 24 by context, `--r-xl` → `--pd-radius-dialog`); the few Pitwall-only layout values
  that have no family token (title-bar inset) are `--pw-*` locals defined once.
- The chart colours come from the shared palette (`--pd-chart-*`); `shared/theme-tokens.ts` mirrors `--pd-*` values for
  ECharts and its contrast/CVD test is replaced by a test that every mirrored value equals the shared token.
- Acceptance:
  - a unit test fails on any `var(--x)` in `src/**/*.{ts,scss}` that is not `--pd-*`, `--pw-*`, `--mat-*`/`--mdc-*` or a
    component-local property declared in the same file;
  - `styles.scss` declares no colour literal;
  - the app follows `data-theme`, `data-accent`, `data-density` (spec: the root variables change with each);
  - layout and axe baselines: no new line; unit tests, lint and build green; screenshots of every route in both themes.

### WP-2.2 Layout at 900, 1024 and 1280 px (no shared change)

- Every line of `e2e/layout.baseline.json` fixed at its cause: tables that scroll inside their panel instead of the page,
  forms whose grids step down (four → two → one column) by container width, filters that wrap, the requests table's
  columns that give way by priority, the dashboard apps card as a table that fits its column.
- Acceptance: `layout.baseline.json` is `{}` for chromium at 900, 1024 and 1280 and WebKit passes the same spec; the spec
  keeps failing on any new line; no horizontal page scroll at 900 px.

### WP-2.3 Material and paddock-ui components (no shared change)

- Rule 47, as Dyno did in `8f27d7d22` and `bd60c79c1`: `matButton` (filled = the one primary per region, outlined, text,
  icon buttons with an aria-label and tooltip), `mat-form-field` inputs, `mat-select` for `pw-select`, `mat-button-toggle` for
  segmented controls (or `pd-segmented-control`), `mat-tab-nav-bar`/`mat-tab-group`, `mat-menu` for `pw-row-menu` and the
  context menu (`matContextMenuTriggerFor` with `pdContextMenuKeys`, Shift+F10), `mat-progress-bar`, `mat-checkbox` in
  forms and `mat-slide-toggle` for immediate settings.
- paddock-ui: `pd-status-pill`/status dot with a word, `pd-skeleton`, `pd-sparkline`, the shared empty, loading and error
  states, `pd-table`/`mat-table` with sticky headers (C43, ADR 0027) for the requests, models, apps and benchmarks tables,
  the shared toast host.
- Deleted: `.btn`, `pw-select`, `pw-row-menu`, `pw-context-menu`, `pw-skeleton`, `pw-sparkline`, `pw-toast-host`, `pw-empty-state`
  and their styles.
- Acceptance: no native `<select>`, `<input type=checkbox>` or `<button class="btn">` left (a unit test greps the templates);
  each replaced component's spec moves to the Material harness; one primary per region (UI review 2 rule 1) asserted per
  route in e2e; layout and axe baselines stay empty.

### WP-2.4 The app crate on `paddock-shell` (Rust; maybe shared change 1)

- `Cargo.toml`: `paddock-shell` (`tray`, `install`), `paddock-commands`, `paddock-dialogs`, `paddock-window`, `paddock-updater`,
  `paddock-settings`, `paddock-startup` by path; `paddock-shell` with `mock-runtime` for tests.
- `lib.rs` as Dyno's: `APP_ID`/`APP_NAME`/`VERSION`, `command_table!` for Pitwall's commands (window classes MAIN, TRAY,
  DIALOG) behind `Guard`; `shell(place)`; `windows()` (OnClose::Tray, bounds file); `updater()` (the `pitwall-latest` feed,
  the family key, `PluginInstaller`); `app(builder, shell, launch, tray_backend)` with
  `shell.tray(...).launch(launch).add_to(builder)`; `run()` installs `paddock_shell::logging::install` first.
- The tray becomes a `paddock_window::tauri::TrayBackend` over `TrayModel` (kept: it is Pitwall's); the live stream and the
  tray model stay Pitwall's state, set up in `Builder::setup` (state only, no window).
- Deleted: `shell.rs`, `window.rs`, `app_menu.rs`, `native_feel.rs` and the parts of `tray.rs`, `quit.rs`, `updater.rs` the shell
  owns. Commands keep their names (the UI does not change in this package).
- Acceptance: a start test on `paddock_shell::testing::start` (main window and tray exist) and a `--hidden` case (tray, no
  window); C48 (`capabilities/dialog.json`) and C50 pass; `cargo clippy -D warnings`, the app crate's tests and the
  `pitwall-app` coverage unchanged or better; never run on the host (ER-14).

### WP-2.5 The UI on the shell (maybe shared change 2)

- Acceptance: e2e on the shell's main window, settings window and tray popover against the mock backend; no route of the
